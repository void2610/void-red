# 10. 未確定事項 / 要検討

プロトタイプ実装にあたって決める必要がある項目。上ほど優先度が高い。

> **数値バランスは事前に確定させない方針**。
> 入札枚数・対話コマンドの増減量・成功率・共鳴値・制限時間などの具体値は、
> まず仮値で実装し、実際に動かしながら調整する。
> したがって以下の表のうち「数値の決定」に類する項目は、実装のブロッカーとして扱わない。

## 実装時に決めたこと (仕様の空白を埋めた判断)

| 判断 | 理由 |
| --- | --- |
| 0 枚の入札は「不参加」として扱い、全員 0 枚なら流札 | 0 枚同士で競合に入ると誰も上乗せできず膠着する |
| 競合が時間切れでも同数なら、同額の中から抽選で落札者を決める | 流札にすると NPC 同士の競合で記憶が消えすぎる。「最終的に数字が上だった者」の裁定を乱数で代替 |
| 統合時の感情状態は入札の主属性。同数なら記憶の属性 | 歪みが無ければ必ず記憶の属性と一致する、という読みやすい挙動にするため |
| 記憶テーマの鮮明化は「出品の過半 (3/5) を落札」で発動 | 収集率の定義が無かったため、1 階層で閉じる条件にした |
| 観察の成功率 85% / その他 25% は seed 付き乱数 | 検証を決定的にするため。本番は seed 0 (ランダム) |
| 楽園への鍵は「その階層の出品に含まれる鍵ロットを落札していなければ洗礼を受けられない (ゲームオーバー)」 | 「鍵を手にした者だけが楽園へ」を最終階層の敗北条件に落とした |

## オークション本体

| # | 論点 | 状況 |
| --- | --- | --- |
| 1 | 数値バランス (仮値で実装 → 調整) | 対話コマンドの「増加 / 減少」が具体的に何枚なのか、AI の基準入札枚数がいくつなのかが未定義。プロトタイプでは仮値を置いて調整する |
| 2 | 共鳴値が全記憶で未設定 (仮値で実装 → 調整) | 0〜100 の値をどう配分するか。25 個中の目玉の配置ルールも要定義 |
| 3 | 第二価格 (ヴィックリー) 方式の採用可否 | 現行は第一価格。正直な入札が最適戦略になる利点があるが、心理戦の緊張感は薄れる |
| 4 | 競合フェーズの制限時間 | 「制限時間内に誰も追加入札しなければ確定」の具体秒数が未定 |
| 5 | 逆対話の発生確率 | 「一定確率」としか決まっていない。キャラごとの頻度差 (アリア・モルガナは高頻度) をどう数値化するか |
| 6 | 対話コマンドの成功率が上がる条件 | 「初期成功率」と書かれているため上昇要素がある前提。何で上がるのかが未定義 |
